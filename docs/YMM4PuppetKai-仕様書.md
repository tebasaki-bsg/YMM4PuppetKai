# パペット変形改（YMM4）仕様書（たたき台）

2026-11-12 · @tebasaki

## 1. 概要

YMM4 に内蔵されたパペット変形を作り直し、「切れ込み」の機能を加えて軽くした映像エフェクト「パペット変形改」を、別のプラグインとして作ります。元にするのは、ユーザーの仕様書「パペット変形 挙動仕様（YMM4 版の作り直し用）」（AviUtl2 版 v0.3.2 で確定した挙動）です。この文書は、それに 2026-11-12 までに決まったことを加えたものです。

- **ピン**：画像上の点です。その点を動かすと、周りの画像が引っ張られて変形します。
- **ボーン**：関節を親子でつないだ骨組みです。角度・伸縮・揺れで、腕のような物体を関節ごとに動かします。
- **切れ込み（新しい機能）**：紙に切れ込みを入れるように線分を引くと、その線の両側が分かれて別々に動きます。
- 変形方式は「剛体（ARAP）」と「なめらか（MLS）」の2つです。どちらでも切れ込みが効きます。

### 決まったこと（2026-11-12）

| 項目 | 決定 |
|---|---|
| 名前 | プラグイン名はパペット変形改（YMM4PuppetKai）、エフェクト名は「改パペット変形」（2026-11-12 変更）。本体のパペット変形と並べて使えるよう、クラス名・保存名も別にする |
| 切れ込みの形 | 折れ線（1本 2〜32 点。v0.2.0 から。v0.1.0 は直線1本の線分） |
| 切れ込みの最大本数 | 64 本 |
| 切れ込みの端が輪郭の外まで届いていないとき | 延ばさない。描いたとおりに扱う（届いていない端はつながったまま残る） |
| 端の区別 | 編集キャンバスに輪郭の線を表示し、輪郭を越えた端の点は四角、越えていない端の点は丸で表示する |
| 「輪郭」の意味 | 不透明な部分の輪郭。透明な部分がなければ画像の四角 |
| 切れ込みの位置 | 固定（中間点で変わらない） |
| 切れ込みの線の上にあるピン | 始点から終点を見て右側に付ける |
| なめらか（MLS）での切れ込み | 効かせる。MLS を網目の頂点で、網目に沿った距離で計算する方式に変える |
| 網目の描画 | Direct2D の自作エフェクトに頂点バッファと頂点シェーダーを渡し、画像を貼った三角形を描く（本体のパペット変形と同じ公開 API。確認済み） |
| 切れ込みの作り方 | 編集キャンバス右上のハサミのボタンだけ（9章） |
| 本体プレビューでの表示・編集 | ピン・ボーン・切れ込みとも、表示も編集もしない（2026-11-12 決定） |
| 網目からのはみ出しの確認 | 毎フレーム（本体版と同じ） |
| グループ制御 | v0.1.0 は「画像を合成」オンだけ |
| 本体のパペット変形からの取り込み | 作らない |
| 網目 | 輪郭と切れ込みに沿った三角形分割（元の格子は使わない） |
| 切り離されてピンもボーンも無い部分 | 直線距離の MLS で近くのピンに合わせ、形を保って動く |
| 切れ込みの操作 | ピン・ボーン両方のタブで、端の点をピンと同じように操作。削除はタブの「−」（9章） |

- 確認した YMM4：v4.57.0.1（Lite）。本体のパペット変形は `YukkuriMovieMaker.Plugin.Community.dll` の中にあります。

## 4. ピンとボーンの値

元の仕様書の3章と同じです。原点はアイテムの画像の中心、X は右向き、Y は下向き、単位は px、角度の正は時計回りです。

### ピン

| 項目 | 種類 | 単位 | 範囲 | 初期値 | 表示桁 |
|---|---|---|---|---|---|
| 有効 | 固定値（オン／オフ） |  |  | オン |  |
| 基準X / 基準Y | 固定値 | px | ±100000 | 追加した位置 | 0.1 |
| 移動X / 移動Y | アニメーション値 | px | ±100000 | 0 | 0.1 |
| 紐付くボーン | 内部の値 |  |  | なし |  |

- 無効なピンは基準位置に固定された点になります（紐付けも移動も無視）。
- 移動X/Y はグローバル軸です。数値でのみ変更します。

## 5. 切れ込み

切れ込みは「始点と終点を結ぶ線分」で、線分が不透明な部分を通るところで網目を切り離します。両端は同じ扱いで、「外側の端」「内側の端」の区別はありません。

### 5.2 開いた端と閉じた端

- **開いた端**：輪郭の外にある端です。そこまで切れているので、両側が分かれます。編集キャンバスでは**四角**で表示します。
- **閉じた端**：輪郭の内側にある端です。切れ込みはそこで止まり、その先はつながったままです。編集キャンバスでは**丸**で表示します。
- 組み合わせごとの動き：

| 端 | 動き |
|---|---|
| 片方が開いた端 | 紙の切れ込み。開いた端の側から V 字に開く |
| 両方とも閉じた端 | 穴。口や袋の口のように、周りはつながったまま開く |
| 両方とも開いた端 | 完全に2つに分かれる |

- 「輪郭」は、網目を作った不透明な部分の輪郭です（6.1）。編集キャンバスに線で表示するものと同じで、端の形もこの線で決めます。画像に透明な部分がなければ、画像の四角が輪郭です。
- 閉じた端が輪郭のすぐ手前にあると、細い橋でつながったまま残ります。橋の太さは実際の距離ではなく、網目の間隔（8〜12px ほど）で決まります。端の形を見れば、この状態かどうか分かります。
- 切れ込みどうしが交わるときは、交点で両方を切ります。
- 切れ込みの線の上にあるピン（ボーンの線上の制御点も含む）は、始点から終点を見て右側の三角形に付けます。完全に切り離されてピンもボーンも無くなった部分（透明な隙間で離れた図形も同じ）は、直線距離の MLS で近くのピンに合わせ、形を保って動きます（AviUtl2 版と同じ考え方）。

切り離された部分の動き（採用は右の B）。両端とも開いた切れ込みで左下を切り離し、右上の大きい部分の4本のピン（白い丸）だけを動かしたものです。

## 6. 変形の計算

ボーン・揺れ・ピンの現在位置・制御点は、元の仕様書の 4.1〜4.4 と同じです。切れ込みのために変えるのは、網目の作り方と、MLS の距離の測り方です。

### 6.1 網目

1. 入力画像の不透明な部分（α > 0）の輪郭を取り、折れ線にします。
2. 輪郭と切れ込みの線分を「必ず辺にする線」にして、内側をほぼ正三角形の三角形に分けます（Delaunay 分割）。
3. 切れ込みの線上の頂点を2つに複製し、線の左右の三角形に別々の頂点を持たせます。閉じた端の頂点だけは複製せず、左右で共有します。

- 三角形の数の上限は 5,440 個です（本体版と同じ）。間隔は、不透明な部分の面積から上限に収まるように決め、最小 8px です。
- 元の仕様書の「長い辺 64 分割の格子」は、切れ込みが斜めにセルを横切ると切り口がギザギザになるので、使いません。
- 網目は、入力の不透明な部分か切れ込みが変わったときだけ作り直します（11章）。

網目の作り方の比較。上が採用した三角形分割、下が元の格子。左から網目、変形後、切れ口の拡大です。

（図：網目の作り方の比較。仕様書の原本を参照）

### 6.2 なめらか（MLS）

- 網目の頂点ごとに、MLS 剛体変形を順方向（変形前 → 変形後）に計算します。画素ごとの計算はしません。
- 重みは元の仕様と同じ w_i = (d_min² ÷ max(d_i², d_min²))^α です。ただし **d_i は網目に沿った距離**（制御点から網目の辺をたどった最短距離）です。切れ込みや透明な隙間をまたいで引っ張られません。
- 距離は、網目か制御点の変形前の位置が変わったときだけ計算し直します。

### 6.3 剛体（ARAP）

- 元の仕様の 4.5 と同じです（初期値 → 相似変換の解 → 局所と大域の繰り返し、Anderson 加速、最大の移動量 0.02px 未満で打ち切り、上限 60 回）。
- 初期値の MLS（α = 1）も、網目に沿った距離で計算します。
- 前のフレームの結果は使いません（表示はその時刻の値だけで決める）。シーク・書き出し・並列描画でも同じ結果になります。
- 連立方程式は帯行列のコレスキー分解で解きます。頂点は帯の幅が小さくなる順（RCM）に並べ、X と Y をまとめて SIMD で解きます。

- ピンもボーンも無いかたまり（5.2）は、初期値を直線距離の MLS で求め、強さ 1×10⁻⁴ でそこに留めます。形は ARAP で保たれます。

## 7. 描画と出力範囲

変形した網目は、Direct2D の自作エフェクトで「変形前の画像を貼った三角形」として描きます。元の仕様書の未決事項4はこれで解決です。

- 使う仕組み：`D2D1CustomShaderEffectImplBase`（YukkuriMovieMaker.Plugin.dll）、`ID2D1EffectContext.CreateVertexBuffer`・`LoadVertexShader`、`ID2D1DrawInfo.SetVertexProcessing`。本体のパペット変形も同じ方法です。
- 頂点ごとに「変形後の位置」と「変形前の位置（画像の貼り付け位置）」を渡します（1頂点 16 バイト）。
- シェーダーは HLSL のソースを DLL に入れ、実行時に YMM4 同梱の D3DCompiler でコンパイルします。
- 切れ口で反対側の画素がにじむ（最大 1px）ときは、貼り付け位置を切れ込みの線から少し内側に寄せて抑えます。
- 出力範囲：変形後の網目が元の範囲からはみ出すときは自動で広げます。中心が動かないよう、上下左右に対称に広げます（元の仕様の 4.7）。

## 8. 中間点と補間

元の仕様書の5章と同じです。中間点ごとの値（移動X/Y、角度、伸縮、揺れ角度、揺れ周期、揺れ伝播、しなり）は YMM4 のアニメーション値にし、値ごとの YMM4 の移動方法を使います。

- 基準X/Y、ジョイントX/Y、揺れ位相、切れ込みの始点・終点は、アニメーション値にしません。
- 区間ごとに移動方法を変えられるかは、YMM4 のアニメーション値の機能の範囲に従います。

## 9. 編集（プロパティ内の編集キャンバス）

ピンとボーンの編集は、元の仕様書の6章と同じです（表示、拡大縮小、操作、ボタン、削除の規則、YMM4 の「元に戻す」への統合）。タブは「ピン」「ボーン」の2つのままで、切れ込みはハサミのボタンで作ります。

### 9.1 切れ込みの作り方と操作

- 編集キャンバス右上の2つのボタン（十字・円形の矢印）の左隣（十字のボタンの左）に、ハサミのボタンを置きます。
- ハサミのボタンを押すと、画像の中央に切れ込みを1本追加します（端の点が2つ出ます）。端は、画像の中心から左右に画像の幅の 1/4 の位置に置き、その切れ込みを選択します。
- 何もない状態から切れ込みを作る方法は、このボタンだけです。キャンバスのクリックやドラッグでは作りません。
- 端の点の操作はピンに準じます：左クリックで選択、ドラッグで位置を変える（0.1px 単位に丸める。押してから離すまでが「元に戻す」の1回分）。当たり判定は半径 10px（画面上）です。
- 上限（64 本）に達しているときは、ハサミのボタンを押せません。
- 折れ線（v0.2.0）：切れ込みの線から 6px 以内をクリックすると、その位置に点を増やして選びます（このままドラッグできる）。両方のタブで、ボーン間の線より優先します。点は 1 本あたり 32 点まで（端を含む）。中間点は「選んで「−」」か「右クリック」でその点だけ消します。始点・終点を選んで「−」は切れ込みごと消し、右クリックでは何もしません。中間点は端ではないので、開いた端・閉じた端の区別はありません（2026-11-13 決定）。
- 切れ込みはピンとボーンの両方のタブで操作できます。切れ込みの点は、ピン・ボーンを足す操作より優先して選ばれます。点を選ぶと、ボタンの下の値の欄が「有効」と、選んだ点の X・Y（見出しは「始点」「中間点 n」「終点」）に替わり、ピン・ボーンを選ぶと元に戻ります。ハサミのボタンで足したときは始点を選びます。

### 9.2 表示

| 対象 | 表示 |
|---|---|
| 輪郭（5.2） | 緑（RGB 34,197,94）の細い線 |
| 切れ込みの線 | 赤（RGB 239,68,68）の線、白い縁取り |
| 開いた端（輪郭の外） | 赤の**四角**、白い縁取り |
| 閉じた端（輪郭の内側） | 赤の**丸**、白い縁取り |
| 選択中の切れ込み | 両端の外側に赤い輪 |
| 無効な切れ込み | 半透明（不透明度 110/255） |

- 端をドラッグしている間も、輪郭を越えた瞬間に丸と四角が切り替わります。

折れ線（v0.2.0）：中間点は端と同じ大きさの赤い丸。選択の印（赤い輪、開いた端は四角の輪）は、選んでいる点だけに付ける（試作2 で変更。上の表の「両端の外側に赤い輪」に代わる）。線にカーソルを合わせると、点が増える位置に薄い赤の丸。

## 10. グループ制御

元の仕様書の7章のとおり、配下のオブジェクト全体を1枚の絵として変形します。ただし、切れ込みのために次の点を変えます。

- 元の仕様の「変形の場を双線形補間で読む」方式は、切れ込みの両側の値を混ぜてしまいます。そこで、点がどちら側の三角形に入るかを判定し、その三角形の値で読みます。
- YMM4 の仕組み（2026-11-06 に確認）：グループ制御の「画像を合成」がオンなら、配下を1枚に合成した画像にエフェクトが1回かかります。この場合は通常のアイテムと同じ処理で済みます。オフなら、配下の各アイテムに別々にかかります。
- v0.1.0 は「画像を合成」オンだけに対応します。オフへの対応は次の版以降です。

## 11. 軽量化

同じ計算時間で、ARAP のずれを最大 10.5px から 0.16px に減らせることを確かめました。GPU 側は、なめらか（MLS）を網目の頂点で計算する形にして軽くします。網目からのはみ出しの確認は、本体版と同じく毎フレーム行います。

### 11.1 計測（CPU、2026-11-12）

手の画像（560×600、ピン8本、網目の頂点 2,159・三角形 3,532）で、ピンを動かし続けたときの値です。作業環境（Linux、2コア）で、本体版の ARAP のコードをそのまま動かして比べました。

| 方式 | 1フレームの計算 | 十分に計算した結果とのずれ |
|---|---|---|
| 本体版（6回で打ち切り） | 9.0ms | 最大 10.5px |
| Anderson 加速（0.02px まで、平均 12.3 回）＋X・Y をまとめて SIMD で解く | 8.9ms | 最大 0.16px |

- 本体版で、網目を作るのに 58〜86ms、行列の分解に 27〜30ms かかりました。どちらも入力や基準位置が変わったときだけです。
- 頂点の並べ方を RCM にすると、帯の幅が 123 から 82 に減りました。解く手間は約2/3、分解は約半分になる見込みです（未計測）。

パペット変形改の段階1（2026-11-12、同じ手の画像・同じ動き）。網目は頂点 2,323・三角形 3,677 です。

| 処理 | 時間 | いつ行うか |
|---|---|---|
| 輪郭 | 6〜7ms | 入力の不透明な部分が変わったとき |
| 網目 | 27〜31ms | 輪郭か切れ込みが変わったとき |
| 網目に沿った距離 | 7ms | 制御点の変形前の位置が変わったとき |
| 行列の分解（2つ） | 37ms | 同上 |
| MLS（初期値） | 0.5ms | 制御点が動いたフレーム |
| ARAP | 8〜10ms（平均 15.7 回） | 同上 |

- 十分に計算した解とのずれは、仕様の打ち切り（0.02px）で最大 1.0px でした（本体版は最大 10.5px）。打ち切りを 0.005px にすると 10ms・0.34px、0.002px で 12.7ms・0.10px です。
- 頂点を RCM で並べ、行ごとに必要な幅だけ持つ分解（スカイライン）にしました。帯行列のままだと、分解は 154ms、1フレームは 26ms かかりました。

- 打ち切りは仕様どおり 0.02px のままにします（2026-11-12 に決定）。

### 11.2 方針

| 対象 | 今の本体版 | パペット変形改 |
|---|---|---|
| 網目からのはみ出しの確認 | 毎フレーム、入力をもう一度描いて GPU から CPU へ読み戻す（GPU の処理が終わるまで待つ） | 毎フレーム確かめる（本体版と同じ）。動画や動く文字で新しく不透明になった部分も表示するため |
| なめらか（MLS） | 画素ごとに最大 320 点を毎フレーム計算するシェーダー | 網目の頂点だけで計算し、GPU は三角形を貼るだけ |
| 剛体（ARAP）の反復 | 6回で打ち切り | Anderson 加速で収束まで。RCM の並べ替えと SIMD |
| 変化のないフレーム | 解き直しはしないが、読み戻しは毎回 | 入力・制御点・設定が同じなら何もしない |

- 実機での速さは、段階2の後に計測用のログを入れて、本体のパペット変形と比べます。
